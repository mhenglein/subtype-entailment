## Source-level cost observations, not a measured ranking

`SummaryAutomaton.states` enumerates all `(B,A)` pairs with B outermost and A
innermost. `encode` is `states.idxOf`; `decode` indexes the states list.
`SummaryInstanceCached.advance` still calls this decode and encode. The cached
state table is reused in Bad/final/flags, but not in those transition calls.
This makes decoding/encoding plausible costs; it does not measure their
contribution after Lean compilation or prove they dominate at n=6.

For n=6 there are 64 subset entries, 4096 physical states and 16,777,216
ordered flag cells. These are exact dimensions of the existing representation,
not a new worst-case bound or measurement of resident memory. Each flag uses
only the source forward subset and the target reverse subset. A matrix with
4096 logical rows therefore needs at most 64 distinct row values; retaining
all 4096 indices is essential.

The existing profiler times one `summary` block, including preparation, and
observes its final-vector size. That is not a five-way construction profile.
Its GNU-time wrapper may be killed with the child process group before it
writes peak RSS. A missing RSS value must remain missing, not zero or an
estimate promoted to an exact peak.

## Diagnostic design and limitations

`profile_raw_summary_66.py` has eight modes:

| Mode | What is actually invoked | Interpretation |
|---|---|---|
| phased | The same cached fields, separately timed, then the same infinite and terminal decisions | Instrumented complete raw query |
| enumeration | Original ordered state list | Isolated construction/forcing probe |
| decode | Original decode over every physical index | Isolated lookup/reconstruction probe |
| lookup | Original state table, then every vector lookup | Isolated table lookup probe |
| successors | Both cached next-set operations on every physical state, without encode | Isolated pair generation, including its state-table prerequisite |
| encode | Precompute all valid successor pairs, then apply original encode to them | Separates subsequent index-search cost |
| flags | Original dense ordered flag formula after the original state table | Isolated flag construction/forcing probe |
| baseline | Current prepared raw endpoint, unchanged complete decision | Uninstrumented `#eval` baseline only |

All n values are restricted to the unchanged empty n=3,4,5,6 family. Every
native process retains the same 20-second limits. A total run of all probes
has several capped processes; it is not a single raw query under 20 seconds.
Times are not additive, because prerequisites, live objects, evaluator effects
and forcing overhead differ. In particular the successors probe includes
building its own state table; the phased transition probe retains the existing
uncached decode calls. Their difference is not a clean causal speedup estimate.

Each diagnostic result is consumed by a finite digest/traversal before its
end marker. Digests prevent an unobserved field from being the only evidence
of completion; they are NOT collision-free semantic equality checks, and
their traversal/printing cost is included in the diagnostic timing. The
original exact full-field checker remains necessary. All flag cells and
physical indices remain represented in the diagnostic, including unreachable
states. The separated constructor is a source-level copy of existing field
formulas, not a newly certified all-input Lean definition.

Only the phased and baseline modes have an entailment interpretation. An
isolated probe's legacy `result:true` is expressly a completion token and is
renamed `probe_completed` in its parsed receipt; it is never an entailment
answer. The parser/runners and resource handling are reused from the existing
modules without editing those files. The extra phase-name set is extended only
inside the new process. Compilation errors and malformed completed markers
remain FAIL; resource interruptions remain UNKNOWN. A missing local runtime
is NOT_READY and yields no native call.

The driver refuses native execution when four critical source blobs differ
from the inspected base, checks Lean 4.33.1, and records current source and
generated-source hashes. Other inherited source hashes are recorded, not
proved equal merely by the critical guard. Build/default-core/full-regression
commands remain separate. GNU-time RSS capture is inherited, including its
honestly reported missing-on-kill limitation; no peak-memory improvement is
claimed. A separately validated killed-process/cgroup accounting method is
still needed if the native n=6 run loses that measurement.

## One conditional representation hypothesis and ordinary proof

This is recorded for later selection only if the profile identifies flag
materialization as the bottleneck. It has not been implemented in the Lean
backend and is not the optimization chosen on measured evidence.

Let U be the existing ordered list `subsets (finRange n)`, and let m=|U|.
Its recursive definition gives m=2^n, so m>0 even when n=0. Let S be the
existing physical state list, with k=m*m entries. The block enumeration gives,
for every p<k,

    S[p] = (U[p div m], U[p mod m]).

This follows directly by indexing the m consecutive blocks
`[(U[i],U[0]),...,(U[i],U[m-1])]`, in outer-index order. Neither a state quotient
nor a different encoding is used.

Define one full row H_i of length k for each i<m by

    H_i[q] = any (x in U[i]) (x belongs to U[q mod m]).

Construct the logical flag matrix by giving physical row p the already
constructed immutable row H_(p div m). Then, for every p,q<k,

    H_(p div m)[q]
      = any (x in S[p].1) (x belongs to S[q].2)
      = flags_cached[p][q].

The first equality is the block-index identity; the second is exactly the
current flag definition. Vector extensionality twice gives equality of the
whole flag matrix. If all other fields are copied unchanged, record equality
gives equality to `SummaryInstanceCached.summaryInstance C M cache a b` for
arbitrary runtime C, M and cache. Cache correctness is unnecessary for this
local representation identity, because the flags do not inspect the cache.
The existing hM/hc hypotheses remain necessary when composing that identity
with `SummaryInstanceCached.summaryInstance_eq` to reach the canonical summary.
The prepared public wrapper supplies them internally, as it already does.

Substitution of the identical Instance into the unchanged two decisions
preserves the raw Boolean and, through the already proved endpoint,
arbitrary-tree entailment on all original inputs. This is a mathematical
composition argument, not a checked new theorem. A future formal module must
prove the index identity, bounds and vector/record equality at the actual
runtime definitions; matching checksums or identical reachable languages
would not discharge this contract.

Ordered flags remain ordered: with p=({0},[]) and q=([],{0}), flag(p,q) is true
while flag(q,p) is false. Diagonal and empty-subset entries are unchanged.
For n=0, U=[[]], S=[([],[])], and the lone flag is false; public Fin 0 query
arguments are uninhabited, but the intermediate matrix identity still holds.
Every unreachable physical row is retained.

At n=6 the proposed table would have 64 stored row values, each still length
4096, with 4096 outer entries referencing them. This is a proposed allocation
strategy, not an empirical memory figure. A compiler might copy/recompute
objects; actual sharing and the complete endpoint cost must be measured.
Even a faster constructor does not establish n=6 raw completion: the unchanged
infinite and terminal branches still have to finish under the same cap.
