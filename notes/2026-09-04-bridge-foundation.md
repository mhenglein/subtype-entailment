# Exact bridge foundation

Date: 2026-09-04

This note records a partial implementation of A010. It builds the exact
regular path-set closure generated by finite seeds and the unconditional roots
of a normalized top-free constraint system. It does not decide Problem 1.7 and
does not implement the unresolved `B`/border-avoidance search.

## Implemented stage

`experiments/topfree_bridge.py` represents the four normalized constraint
forms from Lemma 1.8:

```text
left x right <= target
source <= left x right
source <= target
source <= bottom
```

The first two forms produce the memo's push and pop rules. The first form also
records the unconditional fact that the target has a product root. The final
form records a denial state.

For a finite seed family `(q, w)`, the implementation adds an NFA path from
control state `q` spelling `w` to a final state. It then reverses every rule
of `W` and computes predecessor saturation. The saturation rules are:

* a reverse pop `p --a--> q` adds an NFA edge `p -a-> q`;
* a reverse push `p --push a--> q` and an NFA path beginning at `q` with `a`
  add an epsilon edge from `p` to the remainder state;
* a reverse epsilon rule adds an epsilon edge between control states.

At the fixed point, the NFA language from `q` is exactly the set of stacks
reachable at `q` from the original seeds under forward `W`. This is the
standard finite P-automaton construction, specialized to a leftmost stack
top and binary labels. The implementation computes epsilon closure when
processing push rules, so newly derived epsilon paths are included.

The model checker uses exact regular-language operations on the resulting NFA:

* `letter . L(source) <= L(target)` for product lower bounds;
* `L(source) / letter <= L(target)` for product upper bounds;
* `L(source) <= L(target)` for variable inequalities;
* NFA emptiness for bottom denials.

The prefix-closure check explores the finite subset-state graph. A nonaccepting
subset with an accepting descendant would be a word that is not in the path
set although a longer word is, which is exactly a prefix-closure violation.

`canonical_countermodel` first checks satisfiability from forced roots, then
adds every prefix of a proposed path to the queried source variable and closes
under `W`. It returns `YES` only if all constraints, prefix closure, source
membership, and target separation hold exactly in the regular model. It returns
`UNSAT` when the constraint system has no model. It returns `REJECTED_PATH`
when this supplied path does not work. `REJECTED_PATH` is not an entailment
decision: another, longer path may still be a counterexample.

The 3,577 finite comparisons only compare the NFA with a direct closure whose
intermediate stack height is capped at 16. They are diagnostics for the exact
NFA implementation. They are not used by satisfiability or countermodel
decisions and do not establish an all-length theorem.

The C0 check constructs the canonical infinite countermodel for
`{alpha x beta <= alpha}`, separating `beta <= alpha` at path `10`. The forced
root check rejects `{alpha x beta <= gamma, gamma <= bottom}`. The third check
exercises both quotient and epsilon inclusions. Additional regressions cover
mixed string, integer, and tuple control identifiers, a pop on an empty stack,
a push followed by a pop, and an epsilon transition.

## Audited saturation invariant

Let `P = W^rev`, and let the seed NFA accept exactly the finite seed
configurations. At every saturation stage, an NFA path from `q` spelling `w`
to the final state denotes a reverse-PDS run from `⟨q,w⟩` to one of those
seeds. The three edge additions preserve this invariant directly:

* `p -a-> q` for `p --pop a--> q` removes `a` before following the existing
  run from `q`;
* `p -eps-> r` for `p --push a--> q` uses an existing path
  `q -a-> r`, so the push creates the `a` that the path consumes;
* `p -eps-> q` for an epsilon rule preserves the stack.

Conversely, inspect the first rule of a shortest reverse-PDS run. A pop is
represented by the direct letter edge, an epsilon step by the direct epsilon
edge, and a push by the push saturation rule after the accepting path's first
letter (including epsilon closure). Induction on run length gives completeness
at the fixed point. This is an audit of the standard P-automaton argument;
Lean has not checked it yet.

## Proof obligations and dependencies

The code makes the following mathematical interfaces explicit for later Lean
work:

1. Prove the path-set representation, including the prefix-closed inverse
   tree construction and the arbitrary-infinite-tree semantics (C001).
2. Prove the four normalization rules and the one-step soundness of `W`.
3. Prove P-automaton saturation for the reverse PDS, including epsilon paths
   and the orientation of push versus pop.
4. Prove that the NFA language from each control state is the forward closure
   of the seed family, not merely a bounded approximation.
5. Prove the regular-language inclusion and emptiness checks used by
   `constraint_errors`.
6. Prove that forced-root emptiness of all denials is equivalent to
   satisfiability (Proposition 2.5).
7. Prove that adding all prefixes of `p` and forced roots gives the canonical
   model in Theorem 2.6, including the separate `S`, `F`, and `B` obligations.

The implementation covers the executable shape of obligations 2–5 and the
candidate construction in 7. It does not yet have a proof-assistant proof,
and it deliberately leaves obligations 1, 6, and the global theorem-level
argument open. In particular, exact regular closure for a supplied path does
not bound the set of paths that might need to be searched.
