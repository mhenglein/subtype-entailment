# A capped interface and a checked terminal evaluation gate

Date: 2026-09-20. Workstream A010/A018, C081, E054, #53/#37.
Parent: post-c081-20260919. Starting published main: 98bbcde.

## Target and route

Make the checked finite-expression decision usable on small inputs without
changing its arbitrary-tree semantics. The precise optimization is an
unconditional Boolean equality: first test whether any one-letter reference
is safe, then build one shared promoted query only if such a reference exists.
The original terminal procedure, compiler and semantic theorems stay unchanged.
The complete frontend keeps every existing reflexivity, premise, satisfiability
and root-separation guard. Its new fallback uses the equal gated Boolean.

The disputed obligations are evaluation order and sharing, exact propagation
through the normalized and expression wrappers, and honest capped execution.
The initial per-candidate proposal could rebuild the large query several times;
the global gate repairs that cost claim. The named interfaces and ownership
are agreed in #53. [Profiling and proof](2026-09-20-c081-performance-plan.md).

The implementation is additive. E054 reuses all 38 independent E052 fixtures;
it can also rerun the original implementation under identical caps. Expected
answers come from the original order laws and explicit models. The historical
E052 record is not rewritten. A timeout, resource failure or missing native
result yields UNKNOWN. Passing finite tests is separate from the Boolean proof.

## Interface and trust boundary

From the repository root, with the pinned Lean/Lake on PATH:

```sh
python3 scripts/subtail.py examples/entailment/premise.json --timeout 20
python3 scripts/subtail.py examples/entailment/reverse.json --timeout 20
python3 scripts/subtail.py examples/entailment/zero-spine.json \
  --check-model examples/entailment/zero-spine-model.json
```

A problem contains exactly `variables`, `constraints` and `query`.
An expression is a listed variable name, `"bottom"`, or
`{"prod": [left, right]}`. Each constraint and query is `[left,right]`, meaning
left <= right. The query is not added to the constraints. Empty variable and
constraint lists are supported when the syntax allows them. Names are converted
to checked finite indices; no user-provided string is inserted as Lean code.

The command builds the optional module, runs the complete expression Boolean,
and prints JSON. Exit 0 means ENTAILED or NOT_ENTAILED, exit 2 means UNKNOWN,
and exit 1 means invalid input/model. `--timeout` covers native build and
execution plus the optional explanation search. Linux additionally applies
`--memory-gib` (default 16) to each native process group; macOS does not use
that unreliable address-space limit. A timed-out group is killed and reaped.
Each native process uses one Lean thread. Large inputs can still be impractical.

A NOT_ENTAILED answer attempts a small regular-model explanation. The graph
candidate search uses a fixed library (bottom, root-only, full infinite product,
left spine, right spine), at most 2000 assignments and at most two remaining
seconds. It is incomplete. Failure to find a model is explanation UNKNOWN and
does not retract a completed Lean decision. No countermodel is invented.

The Lean algorithm and equality are checked. The JSON parser, Python launcher,
pretty output and graph checker are ordinary trusted boundary code, covered by
separate tests and review. This is not a theorem about JSON parsing or a Lean-
verified certificate extractor. `--check-model` is a separate independent
negative certificate check and does not claim to run the Lean decision.

## Why the finite graph certificate is exact

A graph node is bottom (`null`) or a pair of child indices. Cycles denote
regular, possibly infinite trees. A root for each input variable specifies a
valuation. Evaluate each finite expression by adding its product nodes and
interpreting bottom as a bottom node. This preserves the expression denotation
by induction on its finite syntax.

For two graph roots, search the finite graph of reachable pairs. A pair with
bottom on the left imposes no further obligation. A product on the left and
bottom on the right is a failure. Two product nodes enqueue both child pairs.
A visited pair need not be revisited: the remaining comparison depends only
on those two roots. There are finitely many pairs, including when the original
graph has cycles. Every reached pair corresponds to its recorded address;
conversely, every product address on the left either reaches a failure or
continues along the matching right product. Thus no failure is equivalent to
product-address inclusion, exactly top-free subtyping.

The checker verifies every premise, then requires a failing query pair. Its
breadth-first search returns a separating address, with `[]` meaning the root.
The empty path is different from no failure. Rechecking the returned graph
against the original JSON reproduces the negative certificate. No finite-tree
assumption enters this proof: the zero-spine example necessarily uses an
infinite value and has a two-node representation.

## Validation plan and limits

- Read the actual Lean wrapper and imported runtime definitions; prove equality
  and semantic correctness without changing the old theorem or its assumptions.
- Pinned native build, optional-module kernel replay and full dependency audit;
  reject unfinished proofs/custom axioms and choice in runtime definitions.
- Run the Python boundary tests, including 676 independent finite-tree address
  comparisons, cyclic models, false premises, root/nonroot failures, parser
  injection attempts, zero variables, missing tools and subprocess timeouts.
- Run E054 with matched original and gated implementations on wb-marcus, each
  with 20-second wall/CPU and 16 GiB address-space caps. Save actual source hashes,
  completed outcomes, UNKNOWN cases and timings. Do not label partial completion
  as a complete native census or an efficient worst-case algorithm.
- Smoke-test the actual JSON commands and supplied graph readback. Record the
  exact combined source revision before publication.

The implementation does not improve the worst-case query materialization or
balanced-table enumeration. A global gate adds a safety scan when a candidate
is safe. There is no promised speedup on every input. The separate C082 witness
bound and reference-algorithm resource account are not practical performance
estimates for this frontend.

## Outcome and next question

The interface and a useful conditional skip are implemented and checked.
The main remaining cost is exhaustive summary/table and query materialization.
A next optimization should cache repeated balanced reachability or avoid
constructing unused summary states, with a semantic equality or simulation
proof. Use these same matched fixtures; report full-expression and raw-backend
coverage separately. A complete regular-countermodel extractor remains future
work; the current small candidate search and exact graph checker are usable
but deliberately incomplete.
