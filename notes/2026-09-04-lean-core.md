# First checked Lean core

Date: 2026-09-04

The first A018 implementation discharges the local binary witness and
truncation obligations. It also checks the conditional finite-budget
enumeration argument. **The global witness bound remains open.**

## Scope and definitions

[Basic.lean](../lean/Subtail/Basic.lean) represents a partial binary DFA using
finite vectors and `Fin k` states. Words are finite lists of Boolean letters.
`stateAt I w i` runs the first `i` letters, returning `none` on an undefined
transition. Safety checks every position, including the initial and final
positions. The witness definition requires the final state to be accepting.

For `i <= j <= length w`, `Agrees w i j` says that `drop j w` is a prefix of
`drop i w`. A witness forbids a flag from the state at `i` to the state at `j`
whenever that agreement holds. This includes diagonal flags and the empty
suffix. `witnessCheck_correct` proves equivalence of this proposition and the
finite Boolean checker.

An independent definition review compared the code with memo Definition 8.1
and C008/C009. It found no mismatch in flag direction, partial transitions,
endpoints, or suffix indices. The review's two requested additions are present:
an explicit empty-prefix example and the maximum characterization `lrs_spec`.

The truncation theorem uses `v = take e w` and `h = lrs v`. It transfers the
suffix of length `h` to the end of `w`, then transfers every shorter suffix.
Every proper earlier occurrence has length at most `h`. Diagonal pairs are
discharged directly from the original witness. These facts handle natural
number subtraction without discarding the `e=0`, `h=0`, or empty-suffix cases.

`IncomingLe new old` is the implication `not G(r,old) -> not G(r,new)` for
every source state `r`. On defined targets, Lean proves that this is exactly
`Pred_G(new) subseteq Pred_G(old)`. Deterministic execution over the shared
suffix derives C009 from C008's state-equality premise.

The visited-state extension compares that implication only at sources
`c(i)` with `i <= e`. Lean checks the strict example `0010 -> 00` and the
failure of the all-state condition on the same instance. See
[the context-cut note](2026-09-04-context-cut.md) for the general written
argument and the finer context variants.

## Conditional decision statement

[Conditional.lean](../lean/Subtail/Conditional.lean) defines a total finite
loop over every pair `L,D` satisfying `L+D <= F(size I)`. The theorem is
parameterized by `size`, `F`, and a Boolean test `success I L D`.

Its two open interfaces are explicit:

```text
sound:
  success I L D = true -> exists w, Witness I w

coverage:
  (exists w, Witness I w) ->
    exists L D, L+D <= F(size I) and success I L D = true
```

The bound is on the budget, not the word length. The code makes no assumption
that these quantities coincide, and no monotonicity assumption on `F`.
There is no classical `Decidable` instance in place of a program. A caller
still has to provide executable definitions of the parameters, implement and
verify the fixed-budget test, and prove coverage for a concrete bound.

## Reproducible validation

Run from the repository root:

```sh
python3 scripts/check_lean.py
```

The pinned version is `leanprover/lean4:v4.33.1`; only the bundled `Std`
library is imported. The command builds the Lean project, replays its compiled
declarations with the bundled kernel checker, and inspects the named axiom
closures. Standard classical axioms occur only within the allowed proof
dependencies; the algorithms do not use classical choice as runtime data.

The executable comparison uses seed `20260904`, 80 generated partial binary
DFAs with 1–5 states, and all words of length 0–6: 10,160 cases. Both Python
witness formulations agree before comparison with Lean. A further 511 words
of length 0–8 compare the longest repeated suffix. Explicit Lean examples
cover empty input, undefined transitions, bad starts, diagonal flags,
empty-prefix cuts, and both strict truncation examples.

The compact result and axiom lists are in
[lean-checks.json](../results/lean-checks.json), indexed as E008. Native
evaluation checks are finite evidence; the all-word implications come from
the proved theorem terms. The theorem audit does not claim that bounded
testing verifies the entire semantics of the original paper.

## Next obligations

O4 is the next formalization target: construct the finite sufficient-condition
automaton and prove its exact language and graph-search specification.
`lrs_spec` is a useful dependency for proving the memo's
`w in S''(lrs w,0)` coverage for each individual witness.

O6 and O7 still need arbitrary-tree semantics, normalization, constructive
satisfiability, and the forward reduction to BorderAvoid. The supplied-path
[bridge foundation](2026-09-04-bridge-foundation.md) is executable Python with
an independent audit, not a Lean proof of those obligations.

None of these local theorems gives a computable global budget bound. That
requires a new argument from A008/A009/A015 or a different complete decision
route. Formalization makes the required statement precise; it does not
establish it by itself.
